# AUDIT (the study report)

This file is the report in the portfolio standard's sense. It keeps
the name AUDIT.md because it was named when the study was built; the
README layout table maps it to its role. Results are in RESULTS.md,
generated by study.analyze; this file holds the claim audit, how the
evidence is protected, threats to validity, and the scorecard of
every hypothesis.

## Security

No credentials, no network calls, no model APIs. The only external
inputs are the pinned packages in requirements.txt. Fault injection is
SIGKILL of the study's own subprocesses on its own work directory.
The LangChain arm's never-imports-langgraph property is enforced by a
test, not by convention.

## Cost

## Maintenance

The study is a frozen measurement. A langchain-core version bump is a
new measurement under ROADMAP.md, never an edit of this one. The
reproduction tests (tests/test_reproduction.py) recompute known answers
from the committed raw files and verify their SHA-256 checksums, so
evidence drift fails CI.

## How the evidence is protected

1. Pre-registration before code and results. PREREGISTRATION.md is
   the first content commit (aa4e555), before the harness commit
   (d6ad6b7) and the results commit (68c43f0). It has not changed
   since: tests/test_layout.py pins its SHA-256 as committed at
   aa4e555, so one changed byte fails CI.
2. Verdicts computed, not typed. study.analyze applies the frozen
   thresholds to results/raw_main.json and results/raw_fault.json and
   writes RESULTS.md and results/summary.json. CI reruns it and fails
   if either file, or any other file under results/, differs from the
   committed copy.
3. Raw evidence pinned. results/SHA256SUMS covers the raw runs, the
   environment record, the fixtures export and the summary;
   tests/test_reproduction.py checks every digest and recomputes the
   two recorded failures from the seeded failure draws.
4. One shared core. The fixtures, policy, tools, executor and scorer
   are verbatim imports from the sibling study, enforced by the
   fixtures hash gate at run time; only the orchestration layer
   differs between arms.
5. The framework arm stays direct. A test proves the LangChain arm
   never imports langgraph, which is installed only as a transitive
   dependency.
6. One registered pass, no retries. The suite ran once; the only
   post-run change was a CI invocation fix that touched no study code
   or evidence (DECISIONS D10).

## Threats to validity

- No model in the loop. The scripted policy measures orchestration
  only; nothing here speaks to framework behaviour under real
  reasoning load (declared scope limit, real-model pass in ROADMAP.md).
- One machine, one suite pass, on a shared VM. Wall-time figures carry
  that machine's state at the time and have no replication.
- Degenerate H1 test. Every paired difference is 0, so the interval is
  [0, 0]: it rules out orchestration-caused success loss on these
  fixtures and carries no further information.
- Implementation-sensitive wall ratio. The native arm commits
  synchronously after every step; a WAL-mode or batched-commit native
  variant is untested, so the ordering may reflect the native design
  rather than framework overhead. No ablation isolates this yet.
- Cross-framework comparison is descriptive. LangChain 0.459 versus
  LangGraph 0.299 rests on two separate native runs.
- Debugging axis not measured (trace units incommensurable across
  arms); carried as a deferral, not closed.
- Fixtures are small, deterministic and synthetic by design; no
  comparability to any published benchmark.
- Version drift. Results hold for langchain 1.4.9 and langchain-core
  1.7.6 only; Dependabot is told not to bump those two pins.
